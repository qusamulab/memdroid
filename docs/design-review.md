## 対象の寿命

`State.Capture` が PID、値型、セッション、対象に固定したドライバーを一度に取得する。
HTTP のメモリ操作と CLI の入力を伴う操作は、この組を使用する。
CLI で入力している間に対象が変わった場合、古い操作はエラーになる。

Attach、Switch、Detach、Close では、旧セッションを無効化し、対象の context をキャンセルする。
常駐処理と進行中の transport 呼び出しの完了を待ってから遷移する。
状態表示のロックはデバイス I/O の待機中に保持しない。

対象切替では旧 Freeze / Watch / Alert を停止し、Undo と snapshot を消去する。
複数 Attach 済みのプロセス一覧は維持するが、バックグラウンド処理は active な対象に限定する。
遅れて戻った snapshot の保存にも対象の一致確認を行う。

ADB の Attach は暗黙の単一端末指定も明示的な serial に固定する。
Attach 済み PID がある間は、選択変更によって既存操作の送信先を変更できない。

## 検索の確定

Session は同時更新操作を拒否する。Reset、型変更、候補の置換、Load、対象切替で旧結果を無効化する。
検索の I/O はロックの外で行い、開始時の revision が一致する場合だけ結果を公開する。
パターン・文字列検索も同じ Session の操作として扱う。

値検索の型は検索成功時に結果と一緒に確定する。無効なリクエストで先に型や候補を変更しない。
候補ページは値型とデータを同じロック内で取得する。

## 保存・復元

保存形式 v2 は process identity と truncation 状態を含む。
ADB の identity は serial、端末の boot ID、PID、`/proc/<pid>/stat` の starttime で構成する。
復元には、そのプロセスへの Attach と identity の一致が必要になる。
PID の一致だけでは、PID 再利用や別端末を同一プロセスとみなさない。

v0 / v1 のブックマークは引き続き読み込める。
identity のない旧形式の候補や、再起動したプロセスの候補はライブセッションへ復元しない。
新しい検索を実行する必要がある。復元に失敗しても現在のブックマークとセッションは変更しない。

## 資源上限

- 値検索: 最大 100,000 候補、保持データの予算 16 MiB。上限判定用に追加 1 件まで読む。
- パターン・文字列検索: 最大 200 候補。全結果を保持してから切り詰める処理を廃止した。
- パターン幅: 200 候補と追加 1 件が 16 MiB に収まる幅まで。
- Filter: 候補順に最大 32 MiB の窓を読み、必要な全リージョンのバッファを同時保持しない。
- Freeze / Watch / Alert: 各 pool 最大 128 タスク、同時 I/O は各 8 件。
- Freeze 値: 1 件あたり最大 64 KiB。一括 Freeze が上限を超える場合はエラーを返す。
- ADB: 各コマンドに 30 秒の期限。対象・タスクのキャンセルでも終了する。
- 保存ファイル: 読み込みは最大 64 MiB。候補の型・幅・アドレス・保持量を検証する。

不完全な検索結果は `truncated` として CLI / API / Web UI へ伝える。
その候補を絞り込んでも完全な検索結果にはならないため、Filter 後もフラグを保持する。
